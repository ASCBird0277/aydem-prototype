# AYDEM visual QA checklist

This checklist keeps the screen-tour visuals human-first. A lesson is not ready because the HTML loads; it is ready when a learner can identify the real control, the callout reaches that control, and the page gives the screen enough room to be understood.

## Pass each time a screen-tour visual changes

- Load the lesson from the Home card, the Learn navigation, and the direct module link.
- Inspect the default Windows PC view at desktop width. The screen gets the dominant visual area; the active explanation stays in a readable side bubble aligned with the screen.
- Select iPhone / iPad and Android phone / tablet. Each view uses a portrait frame, keeps the composer visible, and does not force desktop content into a phone-sized box.
- Select Mac computer. It keeps a wide desktop proportion and does not inherit the phone layout.
- Hover and click markers 1–4. The explanation updates, marker 4 visually connects to the actual message composer, and no marker obscures the text it identifies.
- Keep the instruction "Hover over a numbered marker—or tap it on a phone—to update the explanation panel" directly between the device tabs and the screen visual.
- Click the plus button. The add-file menu opens inside the composer and the explanation identifies “Add photos & files.”
- Check text containment, line length, contrast, focus states, and touch-target size at desktop, tablet, and phone widths.
- Confirm supplied screenshots contain no personal file names, paths, browser tabs, or unrelated desktop content.
- Do not place a screenshot of the AYDEM lesson page inside that same lesson. Learner-facing visuals must show the real device surface or clearly say they are a reference view.
- Recheck the source label and live link whenever the referenced product screen changes.
- Click every forward and back lesson control from a scrolled position. The current lesson should fade out, the new lesson should appear at scroll position 0, and reduced-motion users should not be forced through an animation.

## Current acceptance target

- Windows and Mac: wide, readable desktop screen; message-field explanation in the side bubble, aligned to the screen rather than separated below it.
- iPhone / iPad and Android: centered portrait screen with the screen itself as the focus.
- All four device tabs remain reachable from the same lesson, and the lesson can be opened directly from the module cards and sidebar links.
