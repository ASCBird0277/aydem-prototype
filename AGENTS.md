# AYDEM project rules

## Product intent

AYDEM teaches practical digital skills to adults who may need to revisit a step many times. Every route must support both a first-time top-to-bottom path and direct return to a specific lesson.

## Non-negotiables

- Use plain, dignified language. Never make a learner feel foolish for returning to a lesson.
- Keep course progression separate from resource practice. A practice room may be reachable from anywhere, but it must not replace the next lesson in a module.
- Use the learner's selected device to change instructions and labels.
- Show the real device action wherever the learner acts: native selection, Copy, Paste, file picker, and device-specific controls. AYDEM must never imply that an invented button is the real operating-system action.
- Treat supplied screenshots and verified live captures as the visual authority. Label orientation references as references until an exact capture is available.
- Remove personal filenames, folder names, browser tabs, account details, and unrelated desktop content from teaching visuals.
- Every visual callout must reach the control it names. Check text containment, contrast, keyboard focus, touch size, and responsive layout before approval.
- Preserve direct links to every module lesson and clear return paths to the module, Home, Glossary, and Safe Practice.

## Verification loop

After any route or visual change: inspect the route directly, follow its forward and back links, try its repeat/revisit links, test keyboard focus, test the selected device, and capture the result at desktop and phone widths. Record unresolved exact-capture needs instead of inventing certainty.
